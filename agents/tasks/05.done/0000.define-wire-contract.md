# Define the signed-string wire contract

## Objective
Define and document the canonical representation used to serialize and deserialize Laravel Data objects as signed strings.

## Expected outcome
A written, implementation-ready contract covering:

- HMAC algorithm and digest encoding
- Exact JSON bytes being signed
- Envelope structure and version field
- Standard or URL-safe base64 behavior
- Laravel `app.key` handling, including `base64:` keys
- JSON encoding/decoding rules
- Invalid input and verification failure behavior
- Size, expiry, nonce, replay, and key-rotation decisions

The contract must explicitly state any intentionally deferred security features.

## Evaluation
The contract is considered complete when another agent can implement the codec without making protocol decisions, and when examples are provided for encoding and decoding a representative payload. Security-sensitive choices must have a rationale and tests can be derived directly from the document.
