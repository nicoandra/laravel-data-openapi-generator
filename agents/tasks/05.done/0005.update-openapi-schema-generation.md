# Render marked complex fields as OpenAPI strings

## Objective
Update schema generation so explicitly marked signed-string fields are documented by their transport representation instead of their internal Data structure.

## Expected outcome
`src/Data/Schema.php` and related schema paths emit a string schema for marked fields, preserving relevant nullable, optional, and format behavior. Unmarked complex Data fields continue to emit their existing object or `$ref` schemas.

The behavior must apply consistently to request bodies, responses, and GET-derived parameters where the property is represented as a string.

## Evaluation
Schema regression tests demonstrate that marked fields produce `type: string`, while identical unmarked fields still produce the original complex schema. Generated OpenAPI output contains no accidental component reference for the marked transport field and does not alter unrelated schema behavior.
