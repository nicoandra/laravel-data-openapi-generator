# Identify casted fields for transport representation

## Objective
Define how the document generator recognizes fields whose Laravel Data cast and transformer change a complex runtime type into a string transport value.

## Expected outcome
The implementation uses the configured Laravel Data cast/transformer metadata as the source of truth rather than requiring a second OpenAPI-specific declaration. The supported caster/transformer contract is documented, including how paired casts and transformers are detected and how unrelated custom casts are handled. Existing `ExposedAs` and `ReceivedAs` attributes are either deliberately integrated or explicitly left unrelated.

## Evaluation
Metadata-level tests demonstrate detection of the supported cast/transformer configuration and distinguish it from ordinary complex Data fields. Another contributor can configure the Laravel Data caster and transformer without adding a duplicate documentation marker.
